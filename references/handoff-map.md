# 要素⑧交接表

> **何时加载**：写要素⑧时。**必须落到具名能力**，不许写「继续分析」「后续再定」。
> 交接强度由维度 C（可逆性 × 可机验性）决定：不可逆且可机验 → 走强制闸门；可逆且不可机验 → 走信任 + 抽检。

## 一、交接表

| 能力 | 什么时候交给它 | 验证判据（交接后怎么算完成） |
|---|---|---|
| **确定性脚本 / 机检** | 判定可机验、且需要反复执行 | 零检查对象必须报错；缺陷注入全部被捕获 |
| **skill-creator** | 结论需要落成技能结构、frontmatter 或资源目录 | frontmatter 字段合规；references 引用路径真实存在 |
| **skill-qa-tester** | 已有技能产物，需要行为测试与回归 | 负向用例被捕获 + 合法样本零误报 |
| **cross-review** | 结论会长期生效，需要外部独立挑战 | 至少 2 家独立意见，且每条建议逐条核实过真假 |
| **agent-wiki** | 结论是可复用的行为规则，要沉淀 | 能改变未来决策；有可回指的锚点 |
| **build-expert** | 高后果领域，需要权威源支撑 | 每条断言可溯源到权威标准 |
| **人工裁定** | 不可逆且不可机验 | 决策包四件套齐全：选项 + 对比 + 推荐 + 证据 |

## 二、交接三件套（缺一不可）

1. **具名能力**：写清交给谁，不写「下一步」。
2. **触发条件**：什么情况下启动这一步。
3. **验证判据**：这一步做完，凭什么说完成。

## 三、不许写进要素⑧的空话

`继续分析` ｜ `后续再定` ｜ `待定` ｜ `再说` ｜ `进一步研究` ｜ `看看再说` ｜ `再想想`

这些会被机检直接判 FAIL（B10）。

## 四、边界：什么时候**不**交接

- 问题已在本轮授权范围内、且结论明确 → 直接做，不写交接。
- 交接的唯一理由是「这一步由别人做会更可靠」，不是「我不想继续想了」。
- 若交接对象本身还没确定，写清「需要先确定由谁承接」并给出候选，不要留空。
