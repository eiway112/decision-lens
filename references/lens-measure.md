### M-01 · 评估先于优化（源自 V01）

**主张**：能力上限由评估方法定义——先建基准集与评估维度，再谈使用与优化。

**怎么用**
1. 建长期能力前先写清三件事：基准集在哪、评估维度是什么、谁裁定。
2. 缺任一项先补，不急着调优。
3. 测不出来的维度，不要声称在优化它。

**改变了哪个决策**：原打算「先跑起来看效果再补评估」→ 改为「先写清基准集与维度，否则不启动」。

**什么证据会推翻**：若该能力的效果经证明可被直接业务结果衡量（无需独立基准集），则本透镜可简化。

**何时不该用**：一次性、不复用、且结果可直接目视判定的任务。

**互斥组**：无
**来源**：[公开] Farnam Street, Mental Models https://fs.blog/mental-models/

### M-02 · 生成者不裁定（源自 V02）

**主张**：生成与评估必须角色解耦；模型自评不得作为放行依据。

**怎么用**
1. 关键结论绑定可追溯证据。
2. 自评只能作参考字段，不能作放行位。
3. 裁定方须是独立治具、独立智能体或人。

**改变了哪个决策**：原打算「让模型自己检查一遍再输出」→ 改为「自评留作参考，放行由独立治具判」。

**什么证据会推翻**：若自评与独立裁定在足够样本上一致性达 100%，解耦成本可被质疑——但仍需留证。

**何时不该用**：无独立裁定方且产出无风险时（此时应标注「未裁定的自评」，不是「已通过」）。

**互斥组**：角色分离（M-02 / M-05 / D-08），同组最多选 1
**来源**：[自撰]

### M-03 · 净贡献须配对消融（源自 V05）

**主张**：「有贡献」的断言必须有对照组——净贡献＝完整系统读数 − 配对对照读数。

**怎么用**
1. 报数必报对照。
2. 构造不出消融 → 如实记「净贡献未测」，不用绝对量冒充贡献。
3. 对照须配对（同一批样本），不是另取一批。

**改变了哪个决策**：原打算「加了之后召回 100%，说明有效」→ 改为「去掉它掉多少？没测就是净贡献未测」。

**什么证据会推翻**：若消融在物理上不可构造（该组件是系统成立的前提），则只能测绝对量，须显式标注。

**何时不该用**：组件不可拆卸、无法构造对照时——此时标注「不可消融」，不冒充已测。

**互斥组**：对照与净贡献（M-03 / M-04），同组最多选 1
**来源**：[公开] Mutation testing（变异体存活率即消融思想）https://en.wikipedia.org/wiki/Mutation_testing

### M-04 · 可靠性用 Pass^k 与首错归因（源自 V06）

**主张**：可靠性按连续通过率 Pass^k 报告，而非单次通过率 Pass@k；锁第一个错误并裁定根因责任方。

**怎么用**
1. 报告连续 k 次全通过的概率，不是单次。
2. 锁第一个错误，不拿最后一个报错当根因。
3. 被评估者不得有权修改验证器、测试用例与发布门槛。

**改变了哪个决策**：原打算「单次成功率 60%，可用」→ 改为「连做 5 次全对只有 7.8%，不可用」。

**什么证据会推翻**：若任务本身只需成功一次即可（如检索类），Pass@k 才是对口径。

**何时不该用**：k 无意义的一次性任务。

**互斥组**：对照与净贡献（M-03 / M-04），同组最多选 1
**来源**：[自撰]

### M-05 · 自指度量的分母不得含被评估者的书写自由度（源自 V07）

**主张**：指标口径若落在被评估者能自行改动的自由度上，该指标不可作验收依据。

**怎么用**
1. 逐项审：分子、分母、单位、比较基准——有没有落在被评估者能改的地方。
2. 有 → 换度量，或把分母改成机器可精确枚举的封闭集。
3. 不要靠加纪律约束来救一个失真的指标。

**改变了哪个决策**：原打算「用『有没有写这个字段』当分母考核合规率」→ 改为「分母改机器可枚举的封闭集」。

**什么证据会推翻**：若被评估者经证明无法影响该自由度（有机器强制点），指标可作验收依据。

**何时不该用**：被评估者无任何书写自由度时。

**互斥组**：角色分离（M-02 / M-05 / D-08），同组最多选 1
**来源**：[公开] Goodhart's law https://en.wikipedia.org/wiki/Goodhart%27s_law

### M-06 · 引用分数先审口径（源自 V08）

**主张**：引用任何基准或厂商分数前，先审指标类别、基线口径、裁定来源是否独立。

**怎么用**
1. 五项审计：指标类别 / 基线口径与对照物 / 裁定来源是否独立 / 不明即降级标注 / 全量塞进上下文能否拿同量级分。
2. 任一项不明 → 降级标注，不当结论用。
3. 「检索召回」不是「端到端答对」，不得互换。

**改变了某个决策**：原打算「引用 96.6% 说明效果很好」→ 改为「先审它是召回还是端到端，口径不明就降级」。

**什么证据会推翻**：若该分数的口径经原始来源确认与你的用法一致，则可直引。

**何时不该用**：分数来自一手可核验的官方评测且口径明确时（此时审计可简化）。

**互斥组**：数字口径（M-06 / M-07 / P-10），同组最多选 1
**来源**：[自撰]

### M-07 · 异常读数先溯源，崩溃不折成不达标（源自 V09）

**主张**：面对异常大数字，先拆口径、区分「跑了没过」和「没跑 / 崩溃」，再定性。

**怎么用**
1. 按生产者分桶：真实执行路径 vs 批量体检路径。
2. 检查器必须能区分「执行失败」与「未执行」。
3. 定性结论前先确认是崩溃还是不达标——两者整改方向相反。

**改变了哪个决策**：原打算「指标这么差，说明质量不行」→ 改为「先查是不是系统性崩溃被报成了指标缺陷」。

**什么证据会推翻**：若异常读数经证明来自真实分布（非崩溃），则按不达标处理。

**何时不该用**：读数在正常区间、无异常特征时。

**互斥组**：数字口径（M-06 / M-07 / P-10），同组最多选 1
**来源**：[自撰]

### M-08 · 治具 PASS ≠ 无遗漏（源自 V12）

**主张**：先分清「范围缺口」与「维度缺失」——二者修法代价差一个量级。

**怎么用**
1. 报 PASS 前先确认扫描覆盖面。
2. 范围缺口 → 补一条 glob，代价低。
3. 维度缺失 → 要新造一类检测，代价高；两类分别登记、分别处置。

**改变了哪个决策**：原打算「治具报 PASS，说明没问题」→ 改为「先判是漏扫了目录，还是压根没这个判断维度」。

**什么证据会推翻**：若覆盖面经证明完整（有覆盖率的机器读数），PASS 可信度提升——但仍不等于无维度缺失。

**何时不该用**：覆盖面已被机器证明完整且维度清单已冻结时。

**互斥组**：无
**来源**：[自撰]

### M-09 · 门禁要有量化放行阈值（源自 V14）

**主张**：只拦坏东西、不给「够好了」划线的门禁，自己会变成无限打磨的发动机。

**怎么用**
1. 给结果达标设量化阈值（不是「尽量好」）。
2. 给期望校准设边界（如首轮 2–3 次迭代、C+/B- 为可接受区间）。
3. 三种门禁形态分清：过程合规 / 结果达标 / 期望校准。

**改变了哪个决策**：原打算「加个门禁拦住不合格的」→ 改为「同时写明多少分算够、迭代几轮收手」。

**什么证据会推翻**：若打磨成本经证明低于误放行成本，则无需阈值——但须显式记录这一判断。

**何时不该用**：产出有客观正确性判据（对 / 错二元）时，阈值无意义。

**互斥组**：边界与停止（M-09 / P-01 / D-15 / D-16），同组最多选 1
**来源**：[自撰]

### M-10 · 删除守卫的证据是受控负向用例（源自 G09）

**主张**：「没有报警」不足以证明守卫已无价值；删除前需受控负向用例 + 实际维护成本两项证据。

**怎么用**
1. 删除前先造违规样本，验证它**仍能捕获**。
2. 同时评估维护成本。
3. 两项齐备才删；只凭「一直没报警」不许删。

**改变了哪个决策**：原打算「这个守卫半年没报警，删了」→ 改为「先造个违规样本，看它抓不抓得住」。

**什么证据会推翻**：若守卫在受控负向用例下确实抓不住（已失效），删除成立。

**何时不该用**：守卫的判定对象已不存在（被保护物已下线）时。

**互斥组**：衰减与失效（D-17 / P-09 / M-10），同组最多选 1
**来源**：[公开] Mutation testing（负向用例 / killed mutant）https://en.wikipedia.org/wiki/Mutation_testing

### M-11 · 归因须可回指（源自 G12）

**主张**：凭据须指名 URL 或不少于 7 位的十六进制锚点；「经复核一致」这类散文式表述不作数。

**怎么用**
1. 引用标注到可回指的锚点。
2. 闸门只挡「把非逐字档当原文用」，挡不住标注失真——需人工抽查补位。
3. 指不出锚点的归因，降为「未回指」。

**改变了哪个决策**：原打算「据某资料显示……」→ 改为「指名 URL 或提交号，否则不算归因」。

**什么证据会推翻**：若对象本身无稳定锚点（如口头沟通），须显式标注「无锚点」，不能造假锚点。

**何时不该用**：来源本身不可用锚点标识时——此时标注限制，不豁免。

**互斥组**：无
**来源**：[自撰]

### M-12 · 机制上线前过双门槛（源自 G14）

**主张**：改闸门 / 巡检器必须造「同形态负向用例」验捕获 + 「合法样本」验零误报；两条都过才算修好。

**怎么用**
1. 造一个必须被抓住的坏样本。
2. 造一个必须被放行的好样本。
3. 两道都留档；只看退出码或 pass 布尔会被假绿骗过——WARN 级被捕获时 pass 仍可能是 True。

**改变了哪个决策**：原打算「改完跑一遍，退出码 0 就算修好」→ 改为「坏样本必须被抓、好样本必须被放行，两条都验」。

**什么证据会推翻**：若某类机制无法构造负向用例（判定对象不可造），须标注「无机器判据」，不得静默通过。

**何时不该用**：零检查对象时——此时不是通过，是**失败**（先查探针）。

**互斥组**：无
**来源**：[公开] Mutation testing https://en.wikipedia.org/wiki/Mutation_testing
